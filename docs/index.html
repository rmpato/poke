$ poke + pogo▌

Poke your APIs. Pogo through your requests.

poke runs curl and remembers what it ran. pogo is a terminal UI to find, inspect, replay, edit and diff those requests.

Install GitHub How it works

Your shell remembers the command. It does not remember the response, the status, how long it took, or which of the six nearly identical curl lines in your history was the one that worked.

Type poke where you would have typed curl:

$ poke https://api.example.com/users/42
{
  "id": 42,
  "name": "Pato",
  "active": true
}

Same output, same exit code, same flags — your arguments go to the real curl binary. It just also writes down what happened. Later: 

$ pogo

You never saved anything. You never named a collection. It was just there.

The workflow

  1. Make a request

    Nothing new to learn. It is curl.

    $ poke -X POST https://api.example.com/users \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer $TOKEN" \
    -d '{"name":"Pato"}'

  2. Keep working

    Nothing to save. Nothing to organize. It is already recorded.

  3. Come back when it breaks

    $ pogo

  4. Find it

    Press / and type. Free text, or filters.

  5. Look at it properly

    Press ⏎ for request, response, headers, bodies and timings.

  6. Run it again

    Press r. It becomes a new entry; the original stays put.

  7. Change it and run that

    Press e, edit the curl command, ctrl+r.

  8. See what changed

    Press d on two responses.

Install

$ curl -fsSL https://raw.githubusercontent.com/rmpato/poke/main/install.sh | sh

Or with Go:

$ go install github.com/rmpato/poke/cmd/poke@latest
$ go install github.com/rmpato/poke/cmd/pogo@latest

You need curl on your PATH. That is the only runtime dependency, and it is already on your machine. Update later with poke --update.

Two tools

poke

curl, with a memory.

A wrapper, not a reimplementation. Your argv reaches the real curl untouched, so every flag works, piping works, -o works, -v works, and exit codes match.

Capture rides on side channels that do not disturb curl: -D for response headers, a tee for the body, --write-out for timings.

pogo

the last hundred requests you made, made useful.

History, search, inspection, replay, editing, JSON-aware diffing, copy-as-curl, starring, host grouping.

Everything is a keystroke, the footer always shows what applies, and ? lists the rest. Built with Bubble Tea.

What it does

Remember everything

Method, URL, headers, bodies, status, duration, redirect chain, exit code. Automatically, locally.

Find anything

Free text, or method:POST, status:4xx, host:api.example.com, is:starred.

Inspect deeply

Request and response side by side, query parameters broken out, and a JSON tree you can fold.

Replay instantly

One key. A replay is the same code running the same argv — not a reconstruction of it.

Edit and replay

Change a URL, a header, a body. Run it. The original is never modified.

Compare

Diff two responses. Reordered keys and reformatting are not differences; changed values are.

Where the time went

Timings come from curl's own --write-out. Nothing is estimated: if your curl is too old to report them, pogo says so instead of inventing numbers.

Storage & security

History lives in ~/.local/share/poke as append-only JSONL plus payload files. Directory 0700, files 0600. Nothing encrypted, no account, no cloud, no telemetry — your requests never leave the machine.

The one exception: poke asks GitHub once a day whether a newer release exists, only from an interactive terminal, and only ever prints a line saying so. Installing needs poke --update or a confirmation in pogo. POKE_NO_UPDATE_CHECK=1 switches it off.

Request headers routinely carry credentials, and by default poke stores them as sent. Your history file will contain bearer tokens, cookies and API keys in plain text. That is a trade-off, not an accident: stripping them would make replay silently fail to authenticate. pogo masks secrets on screen, but the file on disk holds the real thing.

If you want the other trade-off, secrets are removed before anything is written:

$ POKE_REDACT=store poke -H "Authorization: Bearer $TOKEN" https://api.example.com/me

Read the security notes before pointing this at production credentials. They are short and they do not hedge.

How it works

   poke <curl args> ──▶ curlargs ──▶ runner ──▶ the real curl
                        (metadata)   (execute + capture)
                                        │
                                     capture ──▶ store  (JSONL + blobs, local)
                                        ▲          │
                                        │          ▼
                          pogo replays ─┘         tui

Both binaries share one execution path, so a replay is the same code running the same argv. Storage knows nothing about the UI, the UI never touches the filesystem, and the curl layer is testable without a network.
